# Playdate VS Code Build Setup

VS Code build and debugging setup for Playdate C API projects.

The setup provides separate workflows for:

- Building and debugging the Playdate Simulator.
- Building the device version.
- Installing the device version.
- Running the device version.
- Removing the installed device game.

## Architecture

```text
.vscode/
├── settings.json
├── tasks.json
├── launch.json
└── vsdevcmd.cmd

scripts/
├── install-device.cmd
├── run-device.cmd
└── uninstall-device.cmd

CMakeLists.txt
```

## Project configuration

`.vscode/settings.json` is the single source of truth for the Playdate project name.

```json
{
    "playdate.gameName": "hello_world"
}
```

For another project, only this value needs to be changed.

The expected PDX names are:

```text
hello_world.pdx
hello_world_DEVICE.pdx
```

The `.pdx` packages are directories generated by the Playdate build tools.

## VS Code

### `settings.json`

Contains project-specific VS Code settings.

Currently the only Playdate-specific setting is:

```text
playdate.gameName
```

This value is passed automatically to the device scripts and is also used by the Simulator debugger.

### `tasks.json`

Contains the build, install, run and uninstall tasks.

### `launch.json`

Contains the Simulator debugger configuration.

### `vsdevcmd.cmd`

Initializes the Visual Studio x64 development environment before running CMake/NMake commands.

## Device scripts

### `install-device.cmd`

Installs the generated device PDX using:

```text
pdutil install
```

The game name is passed by the VS Code task.

### `run-device.cmd`

Runs the installed device PDX using:

```text
pdutil run
```

### `uninstall-device.cmd`

Mounts the Playdate data disk using:

```text
pdutil datadisk
```

The script obtains the drive letter from `pdutil`'s output and removes:

```text
Games\<game>_DEVICE.pdx
```

The PDX directory is removed recursively using Windows `rmdir`.

The script does not attempt to eject the Playdate automatically.

After the PDX is removed, it asks the user to press **A** on the Playdate to leave Data Disk mode.

## Device build

### Generate Device

**Playdate: Generate Device (Release)**

Generates an NMake build in:

```text
build-device-release/
```

using the Playdate ARM toolchain.

### Build Device

**Playdate: Build Device (Release)**

Builds the device target and generates:

```text
<game>_DEVICE.pdx
```

### Install Device

**Playdate: Install Device**

Builds the device version and installs the resulting PDX to the connected Playdate.

### Run Device

**Playdate: Run Device**

Builds, installs and runs the device version.

The task chain is:

```text
Build Device
    ↓
Install Device
    ↓
Run Device
```

## Simulator

### Generate Visual Studio Project

**Playdate: Generate Visual Studio Project**

Generates a Visual Studio 2022 x64 project in:

```text
build-vs/
```

### Build Simulator

**Playdate: Build Simulator (Visual Studio)**

Builds the Simulator configuration using Visual Studio.

### Debug Simulator

**Playdate: Debug Simulator**

The F5 debugger:

1. Builds the Simulator version.
2. Launches `PlaydateSimulator.exe`.
3. Opens the project PDX.
4. Starts the C++ debugger.

The Simulator PDX is selected using:

```text
${config:playdate.gameName}
```

so the game name does not need to be duplicated in `launch.json`.

## Build directories

The Simulator and device builds use separate build directories:

```text
build-vs/
    Visual Studio Simulator build

build-device-release/
    NMake ARM device build
```

This prevents the Simulator and device toolchains from interfering with each other.

## Build toolchain

The device build setup does not depend on a specific Visual Studio version.

`vsdevcmd.cmd` uses Microsoft's `vswhere.exe` to automatically locate the latest installed Visual Studio installation that contains the required MSVC C++ toolchain.

This can be:

- Visual Studio
- Visual Studio Build Tools

The installed version does not need to be a specific release such as 2019 or 2022.

The required Visual Studio component is:

`Microsoft.VisualStudio.Component.VC.Tools.x86.x64`

The script initializes the x64 MSVC environment by calling the detected installation's:

`VC\Auxiliary\Build\vcvars64.bat`

`vswhere.exe` is normally installed with Visual Studio or Visual Studio Build Tools.

## SDK configuration

The Playdate SDK location is provided through:

```text
PLAYDATE_SDK_PATH
```

For example:

```text
PLAYDATE_SDK_PATH=C:\PlaydateSDK
```

The device scripts use this variable to locate:

```text
bin\pdutil.exe
```

The current CMake device task still contains the ARM toolchain path directly in `tasks.json`.

|---|---|
| `.vscode/settings.json` | Single source of truth for the project name |

## Requirements

- Windows
- Visual Studio or Visual Studio Build Tools with the MSVC C++ toolchain
- CMake
- NMake
- ARM GNU toolchain
- Playdate SDK
- VS Code
- Microsoft C/C++ VS Code extension
- `PLAYDATE_SDK_PATH` environment variable
- A connected Playdate for device tasks
